# 結果画面の判定主体を明確にする実装計画

## 解決する問題と理由

結果レーン右端の「○ 一致」「× 不一致」だけでは，誰の予想を何のお題と比較した結果なのかが判別しづらい．研究結果の確認画面では，装飾よりも比較関係を誤解なく読めることを優先する．

## 成功基準

- 上段を「あなたの予想」と明記し，判定を「相手のお題と一致／不一致」と表示する．
- 下段を「相手の予想」と明記し，判定を「あなたのお題と一致／不一致」と表示する．
- 「あなたの予想」は左側の「あなたのお題」に寄せて左揃えにする．
- 「相手の予想」は右側の「相手のお題」に寄せて右揃えにする．
- 上段は「あなたの予想」から相手のお題まで，線を伴う大きな右向き矢印で接続する．
- 下段は相手のお題側の「相手の予想」からあなたのお題まで，線を伴う大きな左向き矢印で接続する．
- ○／×は維持し，矢印を小さな記号ではなく比較関係を示す主要要素として表示する．
- デスクトップとモバイルのどちらでも，予想と判定対象が同じレーン内で読める．

## スコープ

- 結果画面の文言とレイアウトを調整する．
- 双方向判定の計算方法，履歴，ゲーム進行，Firebaseデータは変更しない．

## 制約と依存関係

- 研究システムとして説明文を増やしすぎず，事実関係だけを示す．
- 現在の左右カードと双方向矢印を維持する．
- 本番反映は別途承認後に行う．

## 実装の順序

1. 各レーンへ予想者と比較対象を渡せるよう表示処理を変更する．
2. 上段の内容を左寄せ，下段の内容を右寄せにして，それぞれ予想者側のお題カードへ近づける．
3. 上段を「予想欄 ─────▶」，下段を「◀───── 予想欄」の構造にし，線と矢印の向きを明示する．
4. 判定を予想の直下にある明示的な文として表示する．
5. モバイルでは縦の矢印へ切り替え，2方向を横にずらして重なりを防ぐ．
6. デスクトップとモバイルで表示を確認する．
7. 自動テスト，構文検査，コードレビューを実行する．
