# 参加待ちセッションのキャンセル実装計画

## 解決する問題とその理由

ホストが新しいセッションを作成した後，参加者が来る前に中止したくなっても，現在は最初の画面へ戻る導線がない．ブラウザを閉じてもFirestoreには参加待ちセッションと2人分のお題が残り，同じタブを再読込すると保存済みIDから復帰する．参加前に限り，ホストが明示的にセッションをキャンセルして初期画面へ戻れるようにする．

## 成功基準

- ホストの参加待ち画面に「セッションをキャンセル」を表示する．
- 確認画面で影響を説明し，「待機を続ける」と「キャンセルして戻る」を選べる．
- 確定時は連打を防ぎ，参加待ちセッション，ホスト用お題，ゲスト用お題を一つの原子的操作で削除する．
- 削除できるのは，認証中のホスト本人，`waiting`，`guestUid == null`，ターン開始前をすべて満たす場合だけとする．
- 成功後はリスナー，音声，`sessionStorage`，入力値，セッション状態を解除して開始画面へ戻る．
- 参加処理が先に成立した場合は削除せず，ゲーム画面に残って理由を表示する．キャンセルが先なら参加側は既存の「セッションが見つからない」扱いになる．
- 通信失敗時はFirestoreとローカル状態を維持し，再試行できる．
- ゲスト，第三者，進行中・完了セッションは削除できない．
- 通常ゲーム，チュートリアル，完了セッションを壊さず，自動テストと構文検査が成功する．

## スコープ

対象は待機画面のキャンセル導線，確認ダイアログ，Firestore書き込み契約，Firebase gateway，Security Rules，状態初期化，関連テスト，README，引継ぎ記録である．

ゲーム開始後の退出，途中放棄，完了セッションの削除，管理者用クリーンアップ，既存の孤立セッション一括削除は対象外とする．

## 制約と依存関係

- 現在のRulesはセッション削除を全面禁止しているため，ホスト本人の参加待ちキャンセルだけを許可する必要がある．
- 参加待ち状態ではturnとreflectionはまだ存在せず，削除対象は`session`，`private/host`，`private/guest`の3文書に限定できる．
- root文書だけを削除してsubcollectionを残さないよう，3文書を同じtransactionで削除する．
- 参加とキャンセルの競合はtransactionの再評価に委ね，両方が成功する状態を作らない．
- TDDの公開境界は，Firestore書き込み計画を作る`firestore-contract`と，それを実行するFirebase gatewayとする．DOM内部実装へ密結合したテストは追加しない．このテスト境界は事前提示したシナリオに含まれ，承認済みである．
- GitHubへのpush，Firebase HostingとFirestore Rulesへのdeployは，ローカル実装とレビュー後に別途承認を得る．

## 実装の順序

1. `firestore-contract`のキャンセル条件と3文書削除計画を失敗するテストで固定し，最小実装を追加する．
2. Firebase gatewayへtransaction型のキャンセル処理を追加し，参加処理との競合時に最新状態を再検証する．
3. Security Rulesへ，ホスト本人による参加待ち3文書の同時削除だけを許可する条件を追加する．
4. 待機画面へキャンセルボタンと確認ダイアログを追加し，処理中，成功，競合，通信失敗を表示する．
5. 成功時だけ既存の開始画面復帰処理を呼び，失敗時は待機状態を維持する．
6. 正常系，拒否条件，参加競合，再読込，通常ゲームとチュートリアルの回帰を確認する．
7. 全テスト，構文検査，差分検査，コードレビューを行い，コミットする．

## 未解決の質問

- なし．参加待ちで作成者本人が明示確認した場合だけ，未使用セッションを削除する方針で実装する．
