# チュートリアル文言削除と音量統一の実装計画

## 解決する問題とその理由

開始画面の「セッションデータを作成・保存せず，操作から結果までを約2分で確認できます．」は，チュートリアルボタンと見出しだけで役割を理解できるため不要であり，開始操作の視覚的なノイズになっている．

また，現在の音声エンジンはメロディー，自分の音，相手の音，基本和音へ異なる波形とpeak gainを割り当てている．同じ周波数・開始時刻・長さの検査でも，gainは順に`0.26`，`0.18`，`0.14`，`0.10`となり，同じ音量ではない．所有者は画面の色で識別できるため，音量と音色の差をなくし，配置した音そのものを比較しやすくする．

## 成功基準

- 開始画面から対象の説明文を削除し，「一人で流れを確認する」と「チュートリアル」だけを残す．
- 説明文の削除後も，「一人で流れを確認する」と「チュートリアル」ボタンの間に削除前と同程度の余白を残す．文章や空要素は追加せず，ボタンの上余白で表現する．
- メロディー，基本和音，自分の音，相手の音について，同じ単音条件では同じoscillator波形と同じpeak gainを使用する．
- 統一値は多声音の全体再生でも過大にならない控えめな値とする．第一候補は全声部を`triangle`，gain `0.10`へ統一する．
- attackとrelease，masterGain，compressor，BPM，再生時間は変更しない．
- 単音の配置確認，通常ゲームの全体再生，チュートリアルの全体再生と履歴再生へ同じ設定が適用される．
- 音程が違っても設定上のgainは同一であることを自動テストで確認する．
- 既存テストと追加テスト，構文検査，ブラウザ操作確認が成功する．

## スコープ

対象は開始画面の説明文，音声エンジンのvoice profile，関連する自動テスト，必要に応じたREADMEと引継ぎ記録である．

ピアノロール，ノート所有者の色分け，音程，和音構成，音声スケジュール，Firestore，チュートリアル状態遷移は変更しない．同時発音数にかかわらず和音全体の聴感音量を完全に同一化する動的正規化も対象外とする．

## 制約と依存関係

- 同じgainでも，周波数，端末，スピーカー，耳の感度により聴感音量は完全には一致しない．今回保証するのは発音単位の波形と設定gainの一致である．
- 複数音が同時に鳴る和音は，単音より合成音量が大きくなる．既存のmasterGainとcompressorで出力を保護する．
- 音色を所有者識別に使わず，既存のピアノロール上の色分けを識別手段とする．
- 通常ゲームとチュートリアルは同じ`audio-engine`を使うため，中央のprofile変更が双方へ反映される．
- commit，GitHubへのpush，Firebase Hostingへのdeployは，ローカル実装とレビュー後に改めて承認を得る．

## 実装の順序

1. 同一条件の全声部が同じoscillatorとpeak gainになることを公開音声エンジン経由のテストで固定し，現状の差で失敗することを確認する．
2. voice profileを共通の波形とgainへ変更し，テストを成功させる．
3. 開始画面から対象の説明文を削除し，ボタンへ上余白を設定して見出しとの間隔を保つ．不要になるCSS指定があれば整理する．
4. 単音，通常の全体再生，チュートリアルの再生・停止と履歴再生を確認する．
5. 全自動テスト，構文検査，差分検査，コードレビューを行う．

## 未解決の質問

- 「すべての音を同じ音量」は，各発音を同じ波形・gainへ揃える意味として扱う．同時発音数の異なる和音全体まで同じ大きさへ正規化すると，音を追加して響きを厚くする効果も弱くなるため，今回は行わない方針を推奨する．
- 統一波形は，矩形波ほど刺激が強くなく，正弦波より倍音を含む`triangle`を推奨する．
