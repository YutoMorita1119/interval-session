# Interval Session

音楽経験の少ない参加者同士が，既存のメロディーへ音を加えながら意図を伝え合う，2人用の研究システムです．即興表現における知識面・時間面の障壁を下げ，「表現→解釈→応答」がターンごとにどう変化するかを記録します．

公開版：https://musical-comms-app.web.app/

## セッションの流れ

1. 1人目がセッションを作成し，表示された6文字のIDを共有する．
2. 2人目が別のタブまたは端末から同じIDを入力して参加する．
3. 各参加者へ異なるお題が割り当てられる．
4. 灰色で初期配置された基本和音を残すか削除しながら，4つの和音を編集する．各和音には基本和音を含めて最大8音を配置できる．
5. 7ターン終了後に，双方のお題と記録を開示する．

各ターンの履歴には，確定時点の盤面を鍵盤・音名・度数付きのピアノロールで表示します．再生ボタンから，そのターンに保存された音を聴き直せます．

初回表示時には，実データを書き込まない3段階の操作確認があります．配置・削除・再生・模擬送信を端末内で試せます．

## 技術構成

- フロントエンド：HTML，CSS，JavaScript ES Modules
- 認証：Firebase Authenticationの匿名認証
- 同期：Cloud Firestoreのリアルタイムリスナー
- 手番確定：Firestore Transaction
- 音声：Web Audio API
- テスト：Node.js標準テストランナー

公開セッション，確定ターン，参加者別の秘密データを別文書へ分離しています．Firestore Security Rulesにより，進行中は本人のお題と記録だけを読み取れ，完了後に双方へ開示します．

## ローカル実行

このリポジトリのルートで静的HTTPサーバーを起動します．

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

`http://127.0.0.1:4173/`を開いてください．実際の同期を確認する場合は，独立した2つのタブで開き，一方で作成，もう一方で参加します．

## テスト

```powershell
npm test
npm run check
```

ゲーム状態，音楽理論上の分類，ノート配置制約，再生予定，Web Audio制御，Firestore書き込み契約，チュートリアル遷移を検証しています．

## データ上の注意

- 表示名，メールアドレスなどの個人情報は要求しません．
- 振り返りはゲーム終了まで相手へ表示されません．
- 現在のお題割り当てはクライアントで行い，Rulesで読み取りを制限しています．開発者ツールを利用する参加者まで含めた厳密な秘匿が必要な実験では，信頼できるバックエンドでのお題割り当てが必要です．
